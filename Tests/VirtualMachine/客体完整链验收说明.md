# 虚拟机内真实文件系统验收

此工具面向 macOS 13、14、15.4 客体，以正式签名应用的 GUI 发起操作，经真实特权助手及内核文件系统完成验证。它不会安装或注册应用，不调用产品 XPC 接口，不调用挂载或卸载命令，不修改安全策略；不需要客体安装开发工具、Python 或 Swift。

0.3.0已有Intel／Apple Silicon通用包，主程序、助手与兼容前端最低macOS13，FSKit扩展最低15.4。优先验证15.4的FSKit路径。13～15.3的兼容路径需要用户安装批准官方macFUSE；[官方说明](https://github.com/macfuse/macfuse/wiki/Getting-Started)明确近期macOS虚拟机不支持第三方内核扩展。此环境应记录安装、界面、助手状态和明确拒绝，完整文件系统验收保持未通过；不能用直接C回调替代，也不为绕过限制修改启动链。候选的VM拒绝规则不禁用15.4及以上FSKit。虚拟机结果不能替代Intel实机、实体USB、跨用户、Windows或掉电验收。

## 本轮已执行结果（截至2026-11-06）

当前为[0.3.1（构建10）源码206af70](https://github.com/dososo/ntfs-writeflow/commit/206af70bb138252bb090064252a47a8ff2bfec69)，尚未发布。222019a根缓存候选收尾47项／架构、原四runner双架构及六目标0、独审已通过；构建10在15.4受控镜像同包完整链已通过，下载仍为0.3.0。本轮发行基于206af70的475项冻结输入；App与DMG分别公证通过，21文件摘要／大小／权限一致，严格签名、Gatekeeper和stapler检查均退出0。构建10在macOS15.4（24E248）ARM客体的受控镜像完整链及内部sync0／close0／RO重开0已核验通过；本机实盘及最终源码分发仍待验。

路由：15.4～26.3只读为系统原生NTFS，读写FSKit；26.4起两种模式均FSKit。15.4至26以前RW用身份桥及内部准备，26.0～26.3 RO／RW均经助手、RW系统命令／可信SUDO_UID保持；26以上funmount保留。26.0～26.3只有策略／模拟回归。工具须按所选模式核验实际ntfs或blntfs、来源、所有者、介质和挂载实例，不能只按系统大版本猜测后端。

- **13.7.4（22H420）／14.0（23A339）ARM客体：** 安装、签名／Gatekeeper、窗口滚动、诊断保存读回已有分项。原镜像标签13.6不代表实测13.6。官方macFUSE5.5安装成功但内核加载27未批准，VFS首步失败、后续未跑；正常raw分离及模板摘要相同。候选明确拒VM旧内核路径，不能写成兼容RO／RW通过。
- **服务和安全：** 13授权记录enabled／allowed但system域无job，助手加载及XPC未验；14登记存在、runs0。两台初始SIP disabled、Authenticated Root enabled、GK enabled；14正常Recovery恢复SIP被Apple请求132拒绝，未恢复，不代表默认安全实体机。
- **15.4既有分项：** 窗口／导出、身份桥与扩展关闭拒绝、系统原生RO已有实际记录；b41 RW创建EROFS，f9及公开IOKit对照资源能力EIO和正常卸载失败，历史原结果保留。
- **阶段四构建8负向：** 公证Accepted且GK通过；prepare遇原资源flush EIO，刷新和重启后仍未就绪、根可读；正常GUI卸载、分离及最终raw与模板摘要相同，原工具false不变。失败清理不等于正向RW通过。
- **旧构建7 KOIO诊断：** 普通I/O中文写读／fsync／hash、忙FD拒绝、关FD后内核VFS消失、原生RO重挂复读及分离，工具exit0；deactivate仍报错，不能宣最终cleanclose。
- **构建9开发历史：** 五runner ARM／Rosetta与六目标严格检查0，旧收尾33项覆盖真实普通文件引擎、忙／force零字节变化、原错锁存及同实例重激活；不等于客体VFS。

**构建9实际结果：** fresh链VFS全部步骤、工具退出0，但deactivate Code16，完整FAIL。原应用重启后登记更替／插件启动异常及工具交互中断单独保留，不与fresh链最终错误混算。

**构建10同包实际通过：** macOS15.4（24E248）ARM客体，构建10／206af70受控镜像完整链通过：原生RO拒写、中文65,573字节写入／fsync／摘要、持FD占用拒绝、关闭FD后正常卸载、RO重挂复读及正常分离；扩展另核sync0／close0／RO重开0。 同模块停用日志显示非force、全部打开1／非根0，随后sync0／close0／RO重开0，无该模块停用错误16。归档与raw检查前后未变，最终镜像只读快速预检及卷标志0，专用payload离线复读摘要一致。该结论不覆盖挂载中App退出／重新启动、LS替换登记、其他系统或实体盘；构建9原失败不改判。

旧FSKit未全部保留nosuid／nodev／nobrowse；特殊项拒绝、不呈现setuid／setgid不能替代内核标志。公开inhibit有效位原断言仍红，现代模块静态能力的真实行为仍待核。详细历史与未覆盖见[六项核验](../../发布/0.3.1可核验说明.md)。

现代系统本轮改用本机macOS26.6.2与已授权5TB外部USB的一轮实际验收，文件写读／同步／占用拒绝／RO重挂结果尚待。不会额外启动26.4 VM；26.4仅处镜像准备，未启动、未通过。只读DA／IOMedia元数据验证不等于实盘文件操作成功。

## 准备工具与输入

仅在宿主编译普通可执行文件，不在宿主连接镜像或操作磁盘：

```bash
xcrun swiftc -parse-as-library -target arm64-apple-macos13.0 -swift-version 6 -warnings-as-errors \
  Tests/VirtualMachine/GuestVFSAcceptance.swift \
  -o build/0.3.1-vm/客体输入/WriteFlowGuestAcceptance
```

向客体普通用户的 `~/WriteFlowVM` 复制：正式发行的签名应用 ZIP 和校验清单、独立工具 `WriteFlowGuestAcceptance`、本轮新建的 64 或 128MiB 原始 NTFS 模板。当前输入为 `build/0.3.1-vm/客体输入/WriteFlow-VM-空白NTFS.img`。模板在宿主只作为普通文件生成；客体工具会核对显式摘要并另建独立副本，只连接副本。不要传任何真实设备路径。

客体首先执行只读检查并留档，不能沿用基础镜像的策略假设：

```bash
sw_vers
uname -m
sysctl hw.model kern.hv_vmm_present
csrutil status
csrutil authenticated-root status
spctl --status
shasum -a 256 WriteFlow-VM-空白NTFS.img
```

应用按对应发行说明放入客体固定安装位置后，通过Finder正常启动，核对实际运行包，避免多个副本混淆。保存实际的 `codesign --verify --deep --strict --all-architectures` 与 `spctl --assess --type execute --verbose=4` 结果。SIP、Authenticated Root和Gatekeeper须分别记录；镜像标签、预设状态或其中一项通过不能替代其他项。Gatekeeper若原先禁用，不能视为正常Gatekeeper验收通过。工具不替代这些签名及系统策略检查。

15.4中通过应用和系统设置完成FSKit模块、后台特权助手的正常批准；可能还会出现设备访问或可移动宗卷授权。13～15.3如需复现原版问题，在可丢弃客体记录官方macFUSE安装、正常批准流程和首次真实加载拒绝；候选应明确说明平台不可用，不反复安装或降低保护来追求VFS通过。服务批准后另查登记和运行状态，不凭界面授权状态声称XPC成功。管理员权限仅限客体，不改宿主启动安全、不修改TCC数据库。

远程操作需先由客体 GUI 开启“远程登录”，文件可通过普通 `scp` 传入。交互运行必须使用客体终端，或 `ssh -t` 保留标准输入；应用及系统授权由客体 GUI 完成。

## 最短操作

在客体的 `~/WriteFlowVM` 中执行，将最后一个参数替换为上一步确认的完整模板摘要：

```bash
./WriteFlowGuestAcceptance ./WriteFlow-VM-空白NTFS.img <模板SHA256>
```

工具会先确认虚拟机型号或虚拟化标记、普通用户身份、模板所有权/类型/大小/摘要/NTFS 文件头，再创建客体私有新目录并连接新镜像。每次操作前后核对 `hdiutil` 对确切镜像路径的映射、File 虚拟介质、容量及介质和整盘登记 ID；不接受实体盘。终端输出本轮唯一设备，只在正式应用里选择这一设备。

依终端提示逐步在 GUI 操作，每步明确完成后按回车：

1. 只读挂载：核对内核挂载表的后端类型、root 所有者和本应用私有凭据路径，并验证创建文件返回 `EROFS`。
2. 正常卸载：确认内核挂载消失，完整镜像摘要仍与空白模板相同。
3. 读写挂载：经真实文件系统建立中文目录与 65,573 字节文件，同步后复读 SHA256。
4. 工具保持文件打开期间，在 GUI 尝试卸载，必须截图实际占用错误；回车时工具确认原挂载实例和内容仍保持，然后关闭句柄。仅内核状态检查不能证明 GUI 曾尝试或正确显示失败。
5. 再次正常卸载：GUI 不应有收尾错误。工具确认内核挂载消失并记录镜像摘要。
6. 重新只读挂载：复读先前文件 SHA256，验证 `EROFS`，然后在 GUI 正常卸载。
7. 工具确认最后只读周期未改变镜像，正常分离本轮自有镜像，严格解析系统清单确认映射为零，再检查最终镜像摘要仍与读写卸载后相同，以覆盖分离时的最终刷新；同时确认输入模板摘要未变。未知或错型清单不能视为空清单。

退出码 `0` 只表示上述内核/VFS 检查通过，`1` 表示本轮未通过，`64` 为参数错误，`77` 为宿主、root 或无法确认的客体环境。工具不会把内核卸载消失等同于助手后端收尾成功；GUI 成功/失败、助手回执和系统授权仍须独立取证。

证据在客体 `~/Library/Application Support/NTFSWriteFlow/虚拟机验收/<一次性UUID>`：`结果.json` 包含每步通过项、错误、最终分离后摘要、挂载实例与分离状态；`系统命令-*.log` 和对应 `.stdout` 保存仅本轮系统命令的原始输出。请同时保存 GUI 截图和助手日志，公开前脱敏用户名及路径。

## 失败时

保留应用错误、系统提示、工具证据和本轮镜像。不强制卸载、不杀后端、不删除助手缓存或锁文件、不重置权限。工具仅在确认镜像仍为本轮确切映射且内核已无挂载时尝试正常分离；否则保留现场。

每个工具自行启动的系统命令最多轮询 45 秒，标准输出与错误直接写普通文件，不依赖管道关闭。超时仅向该命令发送一次 `TERM`，立即记录其 PID 并判为失败，即使随后以状态 `0` 退出也不能判成功；主流程随后跳过所有分离清理，避免尚未完成的连接动作与清理竞态。忽略 `TERM` 的命令可能继续运行，必须保留现场并人工检查；工具不发送 `SIGKILL`，不强制分离。此边界只限制命令等待，不代表系统调用或存储故障的全部阻塞情况均有实时保证。

无需任何设备即可在宿主复核命令故障处理，回归专用编译开关不会出现在正常客体产物中：

```bash
xcrun swiftc -parse-as-library -target arm64-apple-macos13.0 -swift-version 6 -warnings-as-errors \
  -D COMMAND_REGRESSION Tests/VirtualMachine/GuestVFSAcceptance.swift \
  -o build/0.3.1-vm/WriteFlowGuestCommandRegression-arm64
build/0.3.1-vm/WriteFlowGuestCommandRegression-arm64 --命令回归
```

该回归仅创建普通日志文件，验证正常输出、忽略 `TERM` 的命令有界超时、`TERM` 后退出 `0` 仍失败、后代持有标准输出不阻塞，以及有效空清单和六种未知结构。子程序自行在两秒后结束；不调用 `hdiutil` 或任何设备接口。将目标和输出后缀替换为 `x86_64` 后可用 `arch -x86_64` 运行同一回归。

客体管理员可按需只读取证：

```bash
sudo launchctl print system/com.blteam.ntfsworkbench.mount-helper
pluginkit -m -A -D -p com.apple.fskit.fsmodule
```

这里的 `sudo` 只用于读取客体服务状态，不用于运行验收工具；不额外执行服务注册、引导、卸载或权限修改。兼容后端的整盘锁和持久回执也只能读取，不能截断或删除。

最小回滚为停止使用此独立工具与移除新增的两个测试文件；它没有修改产品行为。已连接但仍挂载的本轮镜像，必须先由正式应用正常卸载后再正常分离。
