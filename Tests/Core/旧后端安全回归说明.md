# 旧后端安全回归复跑

入口不依赖任何历史版本的build目录。必须显式提供两个真实前置：只读展开的官方macFUSE安装包Payload目录，以及本应用团队正式签名有效、标识不是legacy的助手文件。不能用自定义假库替代官方运行时。测试只读取这些前置，不安装或加载它们。

需要Apple Silicon开发机、Xcode命令行工具、Python 3及Rosetta。脚本以macOS 13为部署目标分别编译ARM与Intel，再在当前主机执行；这不能代替旧系统或Intel硬件验收。必须使用普通用户运行，不需要root。

推荐每次从当前源码重新生成真实C writer产物，再交由Swift生产读取器解析：

```sh
python3 Tests/Core/run_legacy_security_tests.py "$官方Payload目录" "$本应用已签名助手文件"
```

变量由执行者填写实际路径。官方Payload目录内应有`usr/local/lib/libfuse.2.dylib`与`Library/Filesystems/macfuse.fs`。助手必须属于本应用团队，不能是待验证的legacy前端本身；它用于证明相同团队的错误程序标识也被拒绝。

已有真实C writer产物时，可显式提供公共前缀：

```sh
python3 Tests/Core/run_legacy_security_tests.py "$官方Payload目录" "$本应用已签名助手文件" "$C回执公共前缀"
```

脚本分别读取`${C回执公共前缀}-arm64`和`${C回执公共前缀}-x86_64`下的`.pending`、`.status0`、`.status74`、`.syncfail`四个普通文件。成功产物必须对应当前用户、整盘登记ID`9876543210`及token`11111111-2222-4333-8444-555555555555`。状态0通过；进行中、状态74和同步失败均不能被Swift判定为干净关闭。

单独运行已编译测试时，参数同样必须明确：

```sh
"$运行时测试程序" "$官方Payload目录" "$本应用已签名助手文件"
"$Swift回执测试程序" "$某一架构的C回执产物前缀"
```

缺参数退出64，缺少前置退出66。每轮证据写入新建的`build/legacy-security-tests/可复现验证-*`目录，保留命令、原始输出和中文结果，不覆盖旧证据，不自动删除任何历史目录。

本轮检查覆盖签名与架构、篡改副本、读取/写入错误、容量上限、ACL及跨语言回执。没有安装第三方运行时、运行待测前端、加载库、创建root缓存、挂载磁盘或验证实体盘。源码回滚仅需撤回两个测试入口、新脚本及本文；没有系统设置需要恢复。
