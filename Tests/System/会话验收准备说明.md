# 真实产品登录与切用户验收准备工具

工具只准备并收集真实已安装产品的限时日志。不注销、不锁屏、不切用户、不创建账户、不登记登录项、不发送磁盘操作。默认执行`preflight`，只读取产品、偏好和系统元数据；自身编译工具及证据文件写入当前用户Application Support的新建0700目录，不需要GUI应用读取Documents。

这里的安全基线是“自动管理明确关闭、未发现NTFS、没有blntfs挂载”，并非“完全没有元数据查询”。CLI读取磁盘类型元数据、挂载表、进程清单和产品签名，不读取用户文件内容。真实产品仍按生产路径进行元数据查询；没有替换生产代码或模拟真实登录原因。

## 准备与普通冷启动对照

从仓库根目录以当前普通用户执行，禁止sudo：

```sh
/usr/bin/python3 Tests/System/会话验收准备.py preflight
/usr/bin/python3 Tests/System/会话验收准备.py plan --scenario ordinary --duration 3600
```

从第二条输出取得本轮`计划`的绝对路径。部署或签名更新产品之后必须重新plan；旧计划的主程序、Info.plist或签名封套摘要变化会拒绝arm。计划文件0600，只备份固定专用键原值，不备份或改写整个应用偏好域。安全门读取CopyAppValue的有效自动管理值；专用键备份仍精确读取当前用户AnyHost域。有效专用键若被其他来源遮蔽，拒绝arm/disarm，不修改ByHost、受管或全局域。

正常退出真实产品后再明确开启本轮日志：

```sh
/usr/bin/python3 Tests/System/会话验收准备.py arm --plan "本轮计划的绝对路径"
```

arm会重新核查安全基线和安装身份，若发现任何名为NTFSWorkbench的产品主进程仍运行、原专用键发生变化、计划过期或配置异常，会拒绝。CLI不替用户退出应用。唯一写入目标为域`com.blteam.ntfsworkbench`的`writeflow.sessionVerification`，精确四键：版本、编号、创建时间、到期时间。默认一小时、最多六小时，仅开启诊断日志，不授予挂载权限。偏好工具按真实plist类型递归比较字典与数组，区别CFBoolean和CFNumber，在写前比较旧值、写后复读；这不是跨外部进程的原子事务，期间勿由别的工具并发编辑该专用键。

随后由主线程/用户通过正常方式冷启动正式产品，保持至少八秒，不操作磁盘，再正常退出产品。收集普通对照：

```sh
/usr/bin/python3 Tests/System/会话验收准备.py collect --plan "同一本轮计划的绝对路径" --mode ordinary
/usr/bin/python3 Tests/System/会话验收准备.py disarm --plan "同一本轮计划的绝对路径"
```

disarm不依赖应用仍安装、旧安装摘要、磁盘状态或自动管理状态；只读取固定专用键，在其未被遮蔽且仍严格等于本轮配置时恢复原值；原本不存在则删除这一个明确键，不改自动管理、登录项或其他偏好。若键已被后来操作修改，拒绝覆盖。应先正常退出、collect留存完整尾记录，再disarm；提前关闭日志、过期或超过生产每进程每轮256条上限均可能缺尾，缺尾只能判证据不足。操作失败时保留计划、原值备份和日志，不自动猜测恢复。

## 真实登录与切用户

计划目标使用`--scenario login`或`--scenario switch`；收集时可显式使用`--mode login`或`--mode switch`，未指定mode则按原计划。登记真实产品登录项及手动注销/登录/切用户，必须由主线程和队长另外协调；此工具没有这些能力。

普通冷启动对照、真实登录、工作区离开返回和稳定异UID控制台候选分层报告。工作区失活/活动不是跨账户证据；即使同一A进程在失活→返回区间收到1/3/8目标秒采样，记录了稳定B控制台UID、调用会话仍A且不在控制台、无确认和待请求，再在返回区间稳定回到A，也只列异UID候选，真实跨账户仍待独立人工确认B已进入桌面。nil、0、仍A或重复/混杂采样不给B候选。信号只是触发标签，旧timer可能越过下一次切换，分组必须限定在对应序号区间，不能只按标签拼接。普通对照通过只能说明该次普通启动的日志来源、主窗采样与正常退出闭环，真实登录和切用户仍分别显示待测。严格login收集若只有普通对照，保留“普通对照通过、真实登录待测”并退出78，不升格为真实登录通过。

## 日志与失败边界

- 仅读取subsystem `com.blteam.ntfsworkbench`、category `SessionVerification`、前缀`WF_SESSION `的统一日志，保存原始查询结果、命令参数和退出码。日志是证据，不执行其中任何文本。
- 仅支持生产格式2的固定39键、严格类型、固定事件/信号枚举、UTC和有效期限。拒绝重复JSON键、NaN、脱敏、未知字段、混run、缺行、重复序号或缺少正常退出尾。
- 外层`processID`必须等于载荷PID，`processImagePath`必须等于稳定产品可执行路径；同时比对当前UID、版本、构建和主程序摘要。不因载荷自报同一应用标识或SHA就信任其他进程。`senderImagePath`可以来自系统OSLog库，不以此误拒真实产品。
- 每个进程会话需要完整启动头、启动完成、1/3/8秒采样及stop后的正常退出记录。启动完成后原始AppleEvent上下文必须保持一致。
- 真实登录须新进程会话的真实`oapp`/`lgit`、SMAppService已启用、autoOff。检查从启动头到8秒末采样的全部已记录行，不仅检查三个采样；任一可见/最小化内容窗、应用活动、确认或待请求均失败。willFinish的激活策略可能尚未切换，不据此误拒；启动完成之后所有行须为accessory。八秒内主动打开或确认会污染后台样本，不能视为纯后台通过。1/3/8是调度目标，日志日期精度为秒，不代表逐帧零窗或严格计时上界。
- 任意自动管理开启，或出现请求挂载、请求自动挂载、请求卸载、请求弹出，直接判未通过。正常退出仍有磁盘/会话监控或确认也未通过。
- 退出码0表示当前明确范围通过或准备成功；1表示安全/执行失败；78表示证据不足。日志缺失、外层身份不符、未知格式或日志查询失败不等于“没有发生操作”。

## 可核验交付说明

`会话验收准备.py`实现计划、前置条件和分层收集；`会话验收偏好.swift`只读写固定域中的单一键；`会话验收纯测试.py`使用虚构日志和假命令验证拒绝边界，不构成真实登录证据。执行：

```sh
/usr/bin/python3 Tests/System/会话验收纯测试.py
/usr/bin/python3 -m py_compile Tests/System/会话验收准备.py Tests/System/会话验收纯测试.py
```

旧格式1的真实产品普通冷启动已由主线程获得9条完整日志并恢复专用键，但不作为格式2工具通过。独立审查确认旧工具五项缺陷：误把工作区链当跨账户、漏检启动间隔阳性、Swift CFEqual混同布尔和数字、disarm被安装/磁盘阻挡、清洁检出测试父目录缺失。修订先保留4失败+1异常的真实红测，再修复通过；当前33项回归含实际Swift纯compare/inspect入口，不读取或写入真实偏好。格式2/39键及CopyAppValue遮蔽检测已内化进工具，旧证据保留不覆盖。随后主线程用新安装、新计划完成格式2实际普通闭环：9条真实39字段日志、三次窗口采样、正常退出与专用键恢复通过；原始普通启动原因与目标应用登录项未启用均保留，真实登录、切用户仍待用户配合。未覆盖统一日志持久留存的系统保证、异常强杀的完整清理、实体盘、扩展读写或账户权限变化。最小回滚为正常完成本轮后按原计划disarm，逐个撤回四个新增工具文件；证据保留，不批量删除。

原生helper的compare/inspect是有界纯输入检查分支，在任何CFPreferences读取/同步之前返回；只用于隔离比较/有效偏好报告测试。正式read/arm/restore仍固定域和单键。命令输出/错误新建为0600，单命令最长45秒，超时保留部分输出和失败记录，不自动重试权限或扩大日志范围。测试在清洁检出中自行创建明确父目录，不删除既有现场。

补充区间回归：工作区失活至返回，以及返回后到明确主动确认请求之前，检查全部已记录行；任一确认或待请求阳性失败，不再只挑端点/1/3/8样本。明确用户请求后的确认不误称自动重授。该补充先有失败反例，再实现通过。

同值遮蔽补充：除比较精确值与CopyAppValue有效值外，还只读检查专用键CurrentHost是否存在及CFPreferencesAppValueIsForced。即使其值恰好与AnyHost相同，也直接拒绝arm/restore，避免先写后才发现影子。纯inspect输入覆盖这两个同值反例，未在本机ByHost/managed写入测试；不把该风险说成本机已触发。
