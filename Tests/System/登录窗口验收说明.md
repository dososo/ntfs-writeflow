# 原字节生产应用与委托的窗口生命周期验收

此工具直接复制并编译当前`Sources/App/NTFSWorkbenchApp.swift`，包括真实`@main App`、主窗/诊断/设置场景、窗口恢复配置和同一个`WorkbenchDelegate`。没有重写委托或修改生产文件。独立测试依赖提供同名无磁盘模型、最小内容视图及注入的登录原因；不链接生产`AppModel`、`DiskService`或`SMAppService`，不会启动实际磁盘监控、挂载或登记登录项。

## 执行方法

```sh
/usr/bin/python3 Tests/System/登录窗口纯测试.py
/usr/bin/python3 Tests/System/登录窗口验收.py
```

第一条仅执行四项回执身份、早期调用顺序、最小化/隐藏/状态窗分类与未知可见内容窗拒绝测试。先有失败断言，再实现通过，红绿记录留在`build/0.2.0/窗口生命周期开发/`。

第二条不接受外部应用或进程参数，每轮只创建一个唯一新目录和唯一Bundle ID的临时签名应用；冻结原字节生产App及替身，Swift6严格编译后经真实`open`/LaunchServices启动。结束比较生产源字节。每次启动的回执均核对随机令牌、真实PID、实际Bundle路径及ID；只向本轮应用自己的指令文件写入动作，应用正常退出自身。没有`pkill`、信号终止、安装或注销操作；失联时不杀其他进程，独立应用有六十秒自退出兜底。

## 实际检查矩阵

| 场景 | 实际检查 |
| --- | --- |
| 普通启动，菜单偏好开 | 仅主内容窗可见；早期会话订阅调用先于启动监控；普通启动发送一次前台确认请求 |
| 主窗、诊断与设置均打开 | 观察真实NSWindow，不以动作请求成功代替窗口出现 |
| 主窗最小化后重新打开 | 先验证真实最小化，再经LaunchServices恢复主窗 |
| 仅诊断可见时重新打开 | 不因已有辅助窗而漏开主窗，也不重复产生主窗 |
| 关闭最后内容窗 | 自身仍能回复快照，之后LaunchServices可再次打开主窗 |
| 带诊断和设置正常退出，再以注入登录原因启动 | 同一测试Bundle偏好要求保留窗口，生产场景配置仍应无内容窗恢复；初启不发送前台确认请求 |
| 菜单偏好关闭的后台/普通启动 | 后台初启零内容窗，普通初启显示主窗；都可重新打开和关闭末窗保活 |
| 每次明确退出 | 同一生产委托调用`stopMonitoring`替身，随后该PID正常消失 |

每次LaunchServices重新打开都要求前台确认请求累计增加一次。应用记录全部NSWindow的编号、真实标题/类、可见性、最小化与`titled`标记，最小视图仅持弱引用标注角色，不改变窗口标识或恢复设置。未知可见有标题窗口导致失败。主窗、诊断和设置之外的系统状态窗仍完整留证，不混算为产品内容窗。

后台初启还检查五十毫秒轮询和窗口成为主窗、成为键窗、遮挡状态变化通知的观察记录，避免只检查一个最终样本。此观察不能证明小于采样周期、且不触发所监听通知的瞬时画面绝不存在；不作为视觉录像验收。
