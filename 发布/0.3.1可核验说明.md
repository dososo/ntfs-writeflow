# 0.3.1可核验说明草案

日期：2026-11-05。当前为**0.3.1（构建8）私有候选，尚未公开发布**，没有15.4读写完整链通过结论。源码已整合提交为[候选源码提交](https://github.com/dososo/ntfs-writeflow/commit/23479279258f1887eada9c6d6b676d9583d92c05)，安装包／Release尚未发布；公开下载仍为[0.3.0](https://github.com/dososo/ntfs-writeflow/releases/tag/v0.3.0)。本文区分既有客体分项、失败对照、私有候选开发回归和待验场景，不把旧包公证沿用为新候选验收。

Intel／Apple Silicon通用包、主程序与助手最低macOS13、FSKit扩展最低15.4及13～15.3的macFUSE兼容前端，均为0.3.0已有能力。本轮新增旧系统诊断和窗口修正、挂载身份／只读路由，以及扩展内部写入准备与准确状态保护；未重新将Intel打包为首次新增。

## 一、需求拆成哪些可检查行为

| 行为 | 可检查的结果与当前边界 |
| --- | --- |
| Apple虚拟机旧后端明确拒绝 | 仅macFUSE路径、虚拟化标记和完整VirtualMac型号同时匹配时早拒；13.7.4／14.0实际前台拒绝已验证。15.4起FSKit不按该规则禁用，不把旧客体拒绝当VFS通过 |
| 长窗口与诊断可达 | 设置／诊断滚动到底、底部配置／刷新／导出按钮可达，文件保存后实际读回；13.7.4／14.0／15.4已有GUI分项 |
| 漏枚举人工资格与身份桥 | 仅15.4至26以前查询成功但漏本应用时允许人工尝试，`isEnabled`仍false、自动管理仍暂停；等待／错误／明确禁用不放行。独立子进程发现模块，最终类型、来源、root所有者及访问模式核验不放宽 |
| 正确只读路由 | 15.4～26.3只读用系统原生NTFS，核验真实只读位及安全标志；26.4起RO／RW均FSKit。26.0～26.3所有请求经助手、26以上`funmount`保留；这些中间版本只有策略／模拟证据 |
| 写前能力失败保RO、零数据写回 | 仅旧FSKit块资源，从原RO进入RW前对同一原资源执行公开`metadataFlush`能力检查；失败锁存原错误，原RO句柄未被消耗，不建RW后端／引擎。继续读取、正常卸载和整镜像不变已在普通文件故障回归验证，真实FSBlock／客体待验 |
| 后续NTFS预检拒绝的收尾 | 2347927在原RO仍存活时完成旧分支预检／身份／包装器准备，拒绝保RO并锁存原错；双架构按sync→unmount→deactivate测试通过。RO关闭或RW启动后的真实错误仍不伪成功，目标VFS待验 |
| 内部准备与被动状态分开 | 受管RW绑定规范nonce和mediaID；准备前后台修改拒绝。仅精确根项准备属性可执行转换，状态属性不执行转换／同步／清错；磁盘同名属性不得冒充回执。load与activate合并绑定，避免nonce只在load时绕过握手 |
| 不把内核RW当内部可写 | 助手用持有根FD的有界子进程读取有限回执，前后复核票据、FSID及介质。应用只接受精确匹配的`writeReady:true`；缺失、失败或迟到证明显示“写入未就绪”，内核`isReadOnly`原值保留，卸载资格不丢失 |
| 异步等待后复核当前实例 | snapshot／record等待被动RPC后重新读取受影响设备；同media重挂的新token／FSID不能套用旧证明。消失／读取失败撤旧行并计清单不完整，bindings按新记录裁剪；不缓存旧true |
| 特殊项及未知事务保护 | 拒绝Interix字符／块设备、FIFO及socket，枚举隐藏并保留cookie，不修改其数据。未决票据、超时及收尾失败保留现场；特殊项拒绝与不呈现setuid／setgid不等于内核安全标志生效 |

| 应用状态与重读 | `VolumeRecord.needsWriteReadiness`／`access`，`DiskService.recheckingWriteReadiness`与`applyingWriteReadiness`，`snapshot`／`record`；`PrivilegedMountClient.mountedVolumes`单独2秒查询预算；详情橙色状态，历史提示明确为“上次操作” |

固定协议为：选项`writeflow-ready-token=<规范大写UUID>`，准备属性`com.blteam.ntfsworkbench.write-prepare.<UUID>`，被动状态属性`com.blteam.ntfsworkbench.write-ready.<UUID>`。回执是最多1024字节的UTF-8 JSON，仅允许四字段`schema:1`、`token`、正`UInt64 mediaID`、`writable:true`；拒绝额外／重复键、错误类型与错误绑定。它不是写盘探针，也不是每次文件同步成功的替代证明。

## 三、哪些命令与证据验证了行为，边界是什么

### 开发回归

以下新增入口已随上述构建8源码提交；须使用该提交的完整源码与已有双架构引擎，当前0.3.0版本不包含这些入口。它们不安装服务、不执行系统挂载或操作真实盘。

```bash
bash Tests/Core/run_write_readiness_tests.sh
NTFS_TEST_ENGINE_ROOT="$PWD/build/engine" NTFS_TEST_ARCH=universal bash Tests/Engine/run_write_capability.sh
NTFS_TEST_ENGINE_ROOT="$PWD/build/engine" NTFS_TEST_ARCH=universal bash Tests/Engine/run_write_ready.sh
bash Tests/Engine/run_mount_options.sh
NTFS_TEST_ARCH=arm64 bash Tests/Core/run_eject_tests.sh
NTFS_TEST_ARCH=x86_64 bash Tests/Core/run_eject_tests.sh
```

- 共享协议、准确状态、真实AppModel为每架构81项；可挂起RPC的实例重读12项先红后绿，覆盖同media等待间A→B重挂、消失、读取失败、RPC失败与实例未变。原有卷记录32项、弹出58项、挂载状态23项及全应用／界面最低13目标、Swift6警告按错误检查，ARM与x86_64均通过。
- 助手完整核心runner两架构通过，其中18项覆盖私有参数、CLOEXEC原FD经stdin继承、父侧FD仍可用及有界未知结果。普通文件FD继承不是实际FSKit根FD或root命名空间验收。
- 真实普通NTFS镜像覆盖原同步门禁三类故障、零可写工厂／RW引擎／数据写回、RO读取与正常清理、镜像不变；nonce准备前修改拒绝、伪造磁盘属性拒绝、状态查询零IO、不清除写回错误、中文写入／同步及离线复读均有ARM／Rosetta记录。故障闭包不冒充系统FSBlock资源，离线工具仍与产品共享NTFS-3G，不是Windows交叉验证。
- 独立审查发现并修复load阶段nonce漏绑定与RPC等待后陈旧证明两项问题；新测试与各自红例保留。此前诊断转换36项、VM规则25项、原生RO69项、身份桥72项、受管发现85项及特殊项真实引擎各148项属于对应阶段证据，不混算为构建8全部测试数量。

普通镜像／Rosetta、目标版本模拟、双架构编译和类型检查均不能证明Intel硬件或旧系统内核通过。当前文档整理仅核对已有源码、日志及摘要，没有重新运行这些产品测试。

阶段四追加开发核验：`run_write_ready.sh`、`run_write_capability.sh`、`run_mount_options.sh`三个runner均完成ARM／Rosetta并退出0；15.4／26.0／26.4双架构六目标类型检查全0，独立只读审查未发现确定P0／P1。新增用例实际先调用同步，再unmount／deactivate，核验四类预检及能力后身份拒绝的零写／保RO、未转移包装器一次清理；真实RW后的sync／sticky／close错误仍拒绝。阶段四0.3.1（8）通用Release构建、正式签名和`codesign --verify --strict`通过，**未公证、未做新候选VM验收、未发布**，strict通过不能替代公证或Gatekeeper放行。

### 尚未提升的资源能力实验与分发状态

公开KOIO协议的普通IO回退对照不提供物理extent，意外映射／完成入口明确拒绝；公开属性虽读回true，宿主与15.4客体的有效位仍false，断言保持失败。相关Intel内核静态线索不等于ARM执行证明，也不证明已找到可部署修复。**新增KOIO系统能力的客体安装／启用实验待当次明确授权**，不计入构建8已交付功能，不绕过Gatekeeper或有效位失败。

旧私有KOIO包曾完成通用构建和正式签名，未公证包被Gatekeeper拒绝；旧命令默认查询未找到配置不能据此判定丢失。只读复核确认原公证记录存在于数据保护钥匙串（DP），当前真实阻断是宿主锁屏无法取用，需本人解锁后继续，不要求重建凭据。阶段四构建8虽已通过通用Release构建、正式签名和strict校验，仍须独立完成最终App／DMG公证、装订、源码离线对应和附件回下载核验。

备选官方macFUSE5.5 FSKit/local纯内存探针仅完成参数与回调检查，未实际挂载；不计作NTFS或兼容性完成。测试VM恢复既有公证候选、映射归零及正常关闭，不会把早先EIO或卸载失败改判成功。原始证据文件继续保留，公开文档不附私有账户、主机地址、凭据或绝对路径。

## 四、哪些假设来自推断，需要人工确认

- 内部回执必须来自本模块同锁完成的原资源能力检查、预检、身份复核与RW准备；名称、JSON或内核标志本身都不证明真实资源同步和后续写入可靠。只有实际客体可确认根FD／xattr是否按预期回调。
- 原资源能力拒绝及原RO仍存活阶段的只读预检／身份拒绝已有普通文件零写、保RO与正常清理证据；不扩大到RO关闭或RW引擎启动后的真实错误。系统容器notReady后的真实访问及卸载仍待实测。
- 被动查询2秒是客户端超时预算，尚未用真实延迟XPC测墙钟时延；其余磁盘枚举与系统调用不由这项预算保证。探针超时不能等同取消完成。
- 15.4已观察旧FSKit的`nosuid`／`nodev`／`nobrowse`未全部生效，不能仅因传入选项推断受保护。26.0～26.3原生RO路由只有策略／模拟回归，不从15.4分项推断全部系统通过。

## 五、哪些场景没有覆盖

阶段四[修复2347927](https://github.com/dososo/ntfs-writeflow/commit/23479279258f1887eada9c6d6b676d9583d92c05)已修复原先的预检收尾P1并完成独立只读审查：仅旧系统分支把只读quickcheck、身份复核及后端包装器创建前置到原RO关闭之前，拒绝时锁存原错并保RO。暂持包装器未转移时精确清理，成功后才消费RO并开启RW引擎；原RO关闭失败或RW引擎开始后的真实错误仍拒绝，不把空handle的同步改成成功。第一份构建8因该P1阻断，证据保留、制品不可用，不以相同版本号混作阶段四候选。

构建8的真实FSBlock同步能力、root根FD继承、准备／被动状态、超时仍持租约与正常卸载、跨进程恢复、完整GUI读写／同步／忙句柄／重挂复读，以及最终签名制品对应均未完成目标客体验收。旧f9的EIO和卸载失败继续计为未通过，不用新开发回归覆盖历史失败。

Intel实体机、13～15.3实体兼容内核挂载、默认安全全新安装、真实登录／跨用户、实体盘多轮、Windows检查、睡眠、异常拔插、掉电与长期压力未覆盖。[Issue #3](https://github.com/dososo/ntfs-writeflow/issues/3)的macOS27.2实体盘原环境未复测，保持打开。

## 六、最小回滚动作

本轮仅整理公开说明和对应测试核验文档；撤回本轮文档差异不会改变产品、设备或实验结果。构建8源码已提交、安装包仍是未发布候选，停止制品提升／分发即可，不需要修改线上Release、标签和下载入口。

已有应用回退前关闭自动管理、等待事务结束、正常卸载并通过产品移除登记服务后退出，再替换固定位置应用。失败、超时、身份未知或探针尚在执行时保留应用、诊断、票据、锁及回执，不强制卸载、不删锁重试。没有确认干净收尾时，不提示可以拔盘。
