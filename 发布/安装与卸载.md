# 安装、启用与卸载

本说明对应 [0.3.0 兼容预览版](https://github.com/dososo/ntfs-writeflow/releases/tag/v0.3.0)。升级前先阅读[预览范围与回退步骤](0.3.0兼容预览发行说明.md)。下载 DMG 或 ZIP 后先核对同一 Release 的 SHA256SUMS.txt。应用的签名、公证与本机分发核验以该版本Release附件为准；预览版的兼容性范围和未覆盖场景仍以版本说明为准。

## 安装与启用

1. 将签名应用放入个人主目录的“Applications”目录，即 `~/Applications`，再从该固定位置打开并配置服务。保留原有其他 NTFS 驱动，避免直接覆盖未知安装。当前实际验收路径为 `~/Applications/NTFSWriteFlow.app`；系统级 `/Applications` 等其他位置尚未完成完整回归。
2. macOS 15.4 及以上：打开应用，检查系统扩展状态，前往系统设置的文件系统扩展分类启用本应用模块。macOS 13～15.3：不使用 FSKit；先按 [macFUSE 官方说明](https://github.com/macfuse/macfuse/wiki/Getting-Started)自行安装并批准其组件，再打开应用检查“兼容运行时”状态。不要把文件系统运行时检查通过当作内核批准或实际挂载已通过。
3. macOS 26.6.2 上观察到“按 App”开关无响应；本机改用“按类别”，正常重启后发现扩展。该记录不是对所有设备的修复保证。
4. 如需访问物理磁盘，进入应用“设置 → 物理磁盘挂载”，选择“配置管理员挂载服务…”。按 macOS 提示完成管理员授权；若显示等待批准，选择“打开系统授权设置”完成系统批准，再返回应用点击“刷新状态”。确认管理员服务已获授权后再测试挂载。文件系统扩展启用和管理员服务批准是两个独立步骤。
5. 先用可丢弃镜像或专用测试盘验证。已被其他 NTFS 驱动挂载的卷，不能同时交给第二个写入者。先正常卸载原卷，再由本应用挂载，并核对实际来源和所选读写模式。FSKit 路径类型为 `blntfs`；兼容路径为 root 私有一次性目录中的 `macfuse`，不把任意 macFUSE 卷算作本应用所有。兼容后端同整盘同时只允许一个分区会话。旧系统遇其他工具挂载的普通路径卷，应先通过 Finder 或原工具正常卸载。只在新建测试目录进行文件操作，不能把其他驱动报告的可写状态当成本应用读写通过。
6. 拒绝脏卷、休眠卷或不支持的状态时，应按提示在 Windows 正常关机并完成检查，不强制写入。

整盘弹出流程可能另行显示前台 macOS 设备访问认证窗口。请由本人在系统窗口使用 Touch ID 或本机密码完成认证；不要把密码发到聊天、问题报告，或填入应用自定义表单。管理员服务已经获批，不表示系统一定允许当前原始设备操作。取消认证或系统拒绝时，分卷可能已卸载，但整盘仍未弹出；应按错误提示核对状态，不直接断开。0.1.1历史验收中，外部固定 USB 硬盘实测通过安全推出；其设备对象可能仍保留，因为物理连接尚在。只有应用显示“已安全推出，设备仍连接，可以断开”或“磁盘已弹出，可以安全断开连接”时，才按该确认结果断开，不能仅依据“卷已卸载”提示拔盘。

FSKit 路径不要求降低启动安全。macOS 13～15.3 的 Apple Silicon 在使用可选 macFUSE 内核扩展时，可能需要本人按官方流程在恢复模式调整启动安全并批准组件；本应用不会自动更改设置。不愿调整时不要启用这条兼容路径。所有路径均不要求关闭 SIP、禁用 Gatekeeper 或向守护进程添加完全磁盘访问权限。系统拒绝时保留错误，不强制接管。

旧系统卸载在 root 私有一次性目录、目录租约和身份复核下调用正常路径卸载；不承诺抵抗另一个 root 进程绕过仲裁重挂同一路径。26 及以上继续按文件句柄卸载。兼容后端最后写回失败、回执未知或仍持锁时，应用保留凭据并拒绝继续弹盘；不要手工删除 root 缓存、锁或回执来绕过失败。停止写入并保留诊断，待安全移除后在 Windows 检查卷。

## 整盘推出的结果

- 磁盘镜像或可移除介质：成功请求后，原介质对象必须消失，应用显示磁盘已弹出。
- 不可机械弹出、不可移除的外部固定硬盘：成功请求后可能仍保持系统登记；应用必须核验原两层介质身份和容量、同盘无挂载、整棵介质树没有打开引用，才能显示已安全推出但仍连接。
- 占用、身份变化、授权取消、无法读取状态或结果不明确：停止后续操作，不强制推出，也不显示可以断开。分卷可能已卸载，应按提示处理后重试。
- 已推出状态只对应本次插入实例和本应用会话。后续刷新发现重新挂载时会撤销；不要把旧提示当作之后任何时刻都能拔盘的保证。

## 卸载

1. 保持应用和管理员服务可用，关闭所有正在使用本应用挂载卷的文件和 Finder 窗口，在应用中正常卸载所有受管卷，刷新确认实际已卸载。卸载失败时先处理占用，不强制卸载或拔盘，也不要先移除服务。卷卸载不等于整盘弹出；需要断开设备时，在应用中选择“安全弹出整盘”，或通过 Finder 正常推出，等待明确的可断开提示。
2. 进入“设置 → 物理磁盘挂载”，选择“移除挂载服务”，完成系统提示后点击“刷新状态”，确认服务已移除。如报告失败或仍获授权，保留应用并排查，不能直接删除应用包留下仍登记的管理员服务。
3. FSKit 路径在系统设置关闭本应用模块；兼容路径先确认后端已正常退出，再退出主应用。macFUSE 是用户另装的共享组件，本应用不会替用户移除；若要移除，确认没有其他程序依赖它并遵循官方说明。
4. 只将这一个应用包移入废纸篓，保留需要的诊断和源码。不要单独删除包内助手、其他 NTFS 驱动、系统文件或使用批量删除命令。
5. 如有系统登记残留，先核对精确应用路径、服务和模块标识，再按当前系统公开工具处理，不能全量重置 LaunchServices。
6. 重新插入测试盘，检查系统恢复原有挂载行为。真实盘读写与正常卸载已通过，但完整干净环境的安装、移除服务和应用卸载回归仍是发布门禁，未完成前不能标记通过。

源码包解压仅创建普通文件；离线准备脚本仅为随包 NTFS-3G 目录恢复 Git 元数据，不安装驱动或服务。可保留目录供审计。
