# 0.2.0 会话安全续验

日期：2026-10-29。工程候选仍为0.2.0（4），未公开发行。本记录补充并收紧此前的会话方案：普通应用激活不再独立授予自动挂载会话确认，必须有当前撤销代的显式操作请求。实体20轮、目标机和正式发布门槛保留。

## 实际实现与检查入口

| 行为 | 文件、函数 | 验证 |
| --- | --- | --- |
| 启动早期安装会话通知，磁盘监控稍后启动时不重置状态 | NTFSWorkbenchApp.swift的applicationWillFinishLaunching；AppModel.startAutomaticSessionMonitoring | 生产App原字节窗口宿主检查调用顺序；真实模型重复启动保持DP/睡眠闭锁 |
| 受保护数据负向状态独立闭锁，属性true不能提前解除；匹配恢复事件也不直接授权 | AutoMountSessionState.observeProtectedData／protectedDataBecameAvailable；AutoMountSessionMonitor | 旧实现实际触发断言失败；修复后过渡与交叉状态测试通过 |
| 睡眠、工作区失活分别闭锁；唤醒和切回只解除各自闭锁，均需新确认 | AutoMountSessionState.setSleeping／setWorkspaceActive；AppModel.receiveAutomaticSessionEvent | 隔离NotificationCenter真实生产接线；等待record的事件被撤销、已提交mount继续持锁 |
| 控制台身份失效永久撤销旧确认，不因身份恢复而复活 | AppModel.observeAutomaticSessionSnapshot | 无通知的false→true快照组合及待激活请求撤销测试 |
| 用户操作建立当前撤销代、最多5秒的待激活请求，普通激活只能消费已有请求 | requestAutomaticForegroundConfirmation／completeAutomaticForegroundRequest | 无显式请求的旧激活红测失败；有效、过期、睡眠撤销、控制台撤销、恢复后旧激活均验证 |
| 所有负向通知同步撤销，异步仅查询环境；停止后注销每个通知中心 | AutoMountSessionMonitor.start／stop；AppModel.revokeAutomaticSession／stopMonitoring | 同步接线、重复启动、停止后信号不再影响模型、在途锁及无误报成功检查 |
| 用户有明确恢复入口 | WorkbenchDelegate普通启动/reopen；WorkbenchMenu打开主窗；设置“确认当前会话” | 生产App/委托原字节矩阵；已安装候选设置AX确认按钮可用，自动管理及登录启动保持off |

只有普通用户启动、主动重新打开、菜单打开主窗口、逐盘界面操作或确认按钮创建请求。系统唤醒、工作区恢复、受保护数据恢复、非可信解锁通知和普通激活都不创建请求。请求不是物理在场证明，也不是系统提供的原子屏幕锁定凭证；最终检查到跨进程挂载之间的提交边界继续保留。

独立审查发现并补测有效待激活请求消费及两类启动幂等闭锁；已纳入永久回归。没有放宽介质身份、竞争驱动、助手权限或写前预检。

## 测试结果的等级

1. 纯状态组合：12项覆盖数据保护过渡、睡眠/工作区交叉闭锁、恢复不授予与控制台失效。原有10项状态回归保留。
2. 真正AppModel通知接线：使用隔离NotificationCenter和快照/磁盘边界注入，覆盖9类信号、当前代显式请求、挂起查询撤销与在途锁。不向系统发送伪锁屏通知。
3. 委托及窗口：直接原字节编译生产NTFSWorkbenchApp.swift与WorkbenchDelegate，替换为无磁盘依赖。四次LaunchServices启动、20个窗口检查通过，包括后台零内容窗、无菜单偏好、辅助窗退出不恢复、关闭最后窗口保活及reopen；登录原因是注入，不能冒充真实登录。后台持续观察不等于逐帧零闪现录像。
4. 真实本机会话观察：队长手动完成一次锁屏→解锁→再次确认→正常结束；隔离宿主链接生产模型及真实通知中心，自动管理始终关闭，磁盘读取/挂载边界均拒绝。本轮从确认true变为锁屏后false，撤销代递增；解锁和随后多次普通激活仍false，用户再次点击后true；正常结束再撤销。不是正式安装应用的完整登录或挂载测试。
5. ARM严格回归及Release构建通过。x86_64完整自动挂载回归在本机Rosetta下实际执行通过；十份x86_64测试产物与翻译执行证据保留。Rosetta不是Intel硬件或旧系统，FSKit加载、签名和真实挂载仍待目标机。

本机锁屏期间DP和控制台快照保持可用/当前用户，没有实际收到公开DP变化、睡眠或工作区切换事件；本次撤销依赖收到的锁屏辅助通知。该通知不是公开稳定契约，因此只认定本机一次观察符合预期，不能提升为跨系统严格锁屏保证。原始信号观察器与生产订阅是不同观察者，原始事件记录可能先于生产处理；以随后生产状态及单调时序判断，不把第一条原始日志等同生产已处理。不能把固定轮询采样的时刻当实际撤销延迟上界。

本机运行证据在build/0.2.0/会话组合续验、build/0.2.0/窗口生命周期-90gv53vv与build/system-tests/真实会话观察-1793257335；这些含本机路径的记录不进入公开源码。观察宿主保留生产DiskService初始化的被动DASession句柄，没有启动磁盘事件监控、执行磁盘命令或调用真实挂载服务。

## 可复现命令

```sh
bash Tests/Core/run_automount_tests.sh
NTFS_TEST_ARCH=x86_64 bash Tests/Core/run_automount_tests.sh
python3 Tests/System/登录窗口纯测试.py
python3 Tests/System/登录窗口验收.py
python3 -m unittest discover -s Tests/Compatibility -p 'test_*.py'
NTFS_BUILD_CONFIGURATION=Release script/build_and_run.sh --build-only
```

x86_64执行要求Intel机器或已安装Rosetta的Apple Silicon，脚本不会安装Rosetta；未知架构在构建前拒绝。真实观察宿主编译与手动操作见[专门说明](../Tests/System/真实会话观察宿主说明.md)。只读观察不自动锁屏、注销、切换账户或修改登录项。

公开API研究以Apple的[初始会话失活通知时序](https://developer.apple.com/documentation/appkit/nsworkspace/sessiondidresignactivenotification)、本机SDK及Apple DTS[数据保护与图形锁屏的边界](https://developer.apple.com/forums/thread/850327)为依据；观察结果不是对所有系统版本的额外承诺。

## 剩余门槛与回滚

仍未覆盖真实SMAppService登录启动、真实睡眠唤醒和快速切换用户、公开通知缺失/延迟的跨系统行为、Intel实机、旧系统运行、干净机完整安装卸载、实体20轮、Paragon实盘性能、Windows及异常断电。只有锁屏解锁不代表睡眠或用户切换已通过。

本轮兼容工具已实际证明固定基线的Intel26完整产物，以及15.4双架构FSKit扩展隔离链接；15.4完整应用保留funmount仅26可用的编译拒绝，没有降级描述符卸载。详情见[兼容记录](0.2.0兼容候选记录.md)。

最小回滚：关闭自动管理，等已接受事务结束并正常卸载自有卷，正常退出后恢复更新前备份。源码逐项撤回会话监控/闭锁/显式请求与新增测试工具即可；不强制卸载、不改用户盘、不撤销系统保护、不对共享分支强推。当前仅草稿审查，不合并、不发布0.2.0。
