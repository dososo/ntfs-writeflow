# 源码、签名与分发说明

面向使用者的介绍、功能和验证边界见根目录 [中文首页](../README.md) 与 [English](../README.en.md)。本文保留离线构建、开发者签名和对应源码分发要求。每个新版本必须独立核验，不能沿用旧二进制的公证结果。

## 构建

要求 Apple Silicon Mac、macOS 26、Xcode 26、macOS 26 SDK、XcodeGen、Autoconf、Automake 与 GNU Libtool。工程的实际构建基线是 Xcode 26.6、macOS SDK 26.5、XcodeGen 2.44.1。依赖工具由开发者从自己的可信渠道安装，本项目不自动安装工具。

从源码候选包解压后，先恢复随包引擎的固定提交元数据，无需访问网络：

```sh
bash 发布/准备离线源码.sh
NTFS_BUILD_CONFIGURATION=Release bash script/build_and_run.sh --build-only
```

源码包包含 NTFS-3G 完整树和公共上游 Git bundle；bundle 的用途是让现有构建脚本离线核对固定版本。仓库克隆方式仍可使用 `git submodule update --init --recursive`。不需要商业 NTFS 驱动参与编译。

上面的 Release 构建输出：`build/xcode/Build/Products/Release/NTFSWorkbench.app`。不设环境变量时默认 Debug。构建脚本采用临时签名，只适用于构建和界面检查，不能把它当成受授权的 FSKit 可分发版本。

## 正式签名

需要开发者自己的 Apple Developer 团队、Developer ID Application 证书及扩展描述文件，描述文件须授权扩展标识 `com.blteam.ntfsworkbench.filesystem` 与 `com.apple.developer.fskit.fsmodule`。不能使用本项目作者的证书或账户配置；源码包不附私钥或描述文件。实际发行若修改标识，应同时调整工程、权限及所有相关标识常量后重新验证。助手与应用之间的固定签名团队要求也必须改为发行者自己的身份，并重新验证双方签名拒绝，不能删除身份检查来让构建通过。

```sh
NTFS_BUILD_CONFIGURATION=Release bash script/sign_app.sh /绝对路径/扩展.provisionprofile '自己的签名身份'
```

签名脚本会验证平台、标识、期限、团队以及实际签名叶证书是否属于描述文件授权证书。签名通过仍需系统启用、运行验证与公证；本候选包不自动公证或上传文件。

## 测试

```sh
bash script/test_engine.sh
bash ThirdParty/FSKitAdapter/Tests/run.sh
python3 -m unittest discover -s Tests -p 'test_signing_gate.py'
```

前两项只创建独立测试文件镜像。系统挂载测试必须先检查相应脚本的范围与前置条件，只用脚本新建镜像；不能把历史设备编号复制到当前机器。真实介质测试应选定专用测试盘及目录，不操作其他文件。
