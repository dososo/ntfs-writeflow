# 0.2.0 兼容工程候选记录

记录日期：2026-10-29。公开发布范围保持 **macOS 26 及以上、Apple Silicon**。以下是为后续兼容路线完成的工程验证，不是宣布 macOS 13/14/15.4 或 Intel 已可用。没有安装第三方驱动、修改系统安全配置或执行 Intel 程序。

## 实际完成与失败

| 检查 | 结果 | 能证明的范围 |
| --- | --- | --- |
| Intel 固定 NTFS 引擎及离线工具构建 | 通过 | x86_64 Mach-O 和固定源码可编译，未运行 |
| 当前完整应用命令行改 x86_64 | 先失败后通过 | 原固定 ARM 库路径导致链接失败；库和头路径改用 CURRENT_ARCH 后，宿主、扩展、助手均为 x86_64 |
| 默认 ARM 完整应用复验 | 通过 | 默认架构和最低版本保持不变 |
| 完整工程改为15.4目标 | 两架构失败 | ARM遇可用性受限存储属性；Intel遇助手funmount仅26起可用，尚无完整低目标产物 |
| 15.4适配器属性候选 | 仅副本通过 | 改为私有存储加受可用性约束计算属性，完整适配器typecheck通过；未应用到生产 |
| DA公开API以15.4编译 | 两架构通过 | 签名和编译可用性；不证明安全等价 |
| 只读保留磁盘观察器 | 11项通过 | 纯快照策略和自有普通目录读取；无DA操作、无卸载测试 |
| 独立13.0静态NTFS引擎 | 两架构通过 | 64个引擎对象最低目标13.0；当前系统交叉构建 |
| 官方NTFS-3G FUSE前端 | 12个对象通过 | ntfs-3g、lowntfs-3g、common分别以13.0/14.0×ARM/Intel编译 |
| FUSE前端完整链接 | 明确阻断 | 标准位置没有真实macFUSE运行时；构建工具退出78，不造stub、不挂载 |
| 官方离线NTFS探测工具 | 两架构链接通过 | 只在当前26运行ARM只读模式，对新建64MiB普通镜像探测成功，前后SHA256相同 |

初次独立configure因工作路径含空格被Autoconf拒绝，改用相对源码路径后成功；原失败日志保留。前端初编译因官方头文件要求`_FILE_OFFSET_BITS=64`失败，按要求补编译参数后通过。上游`daemon()`弃用警告保留，未改写第三方源码。

## 固定来源与架构取舍

- [NTFS-3G 官方固定源码](https://github.com/tuxera/ntfs-3g/tree/7f0f841fc52cf719106c5c93bafe465004e36816)：`7f0f841fc52cf719106c5c93bafe465004e36816`。Darwin使用external FUSE，不能直接把Linux fuse-lite当作macOS运行时。
- [macFUSE 官方 C API](https://github.com/macfuse/library/tree/7a6cdd2b6e11071a706f4295aa931c65223ba953)：`7a6cdd2b6e11071a706f4295aa931c65223ba953`。本轮只下载头文件及许可证，保留逐文件校验。
- [macFUSE 官方后端说明](https://github.com/macfuse/macfuse/wiki/FUSE-Backends)：FSKit后端要求15.4起。13/14需要独立后端路线；其内核后端在Apple Silicon上的授权要求见[官方入门](https://github.com/macfuse/macfuse/wiki/Getting-Started)。未为验证而安装或降低系统保护。
- [Apple DiskArbitration 官方源码](https://github.com/apple-oss-distributions/DiskArbitration/tree/a542bda934211dc3c301bfdcc7f21349c4164a85)：`a542bda934211dc3c301bfdcc7f21349c4164a85`。DADiskCreateFromIOMedia最终采用BSD名；异步请求传磁盘ID，daemon重查后按路径unmount。公开请求不携带原FD/预期fsid。
- [Apple XNU 官方源码](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/vfs/vfs_syscalls.c)：`f6217f891ac0bb64f3d375211650a4c1ff8ca1ea`。普通非root挂载需要拥有目标目录，root保护空目录能限制直接覆盖；但实际挂载根owner、允许卸载标志、系统特权服务和并发路径解析不能由空目录权限直接推出。

因此不采用`unmount(path)`替换正式`funmount(fd)`。DADiskClaim的独占声明与保留IOMedia有价值，但没有证明消除检查后到异步路径卸载之间的挂载实例变化窗口，正常/占用/身份变化三类DA卸载原型按既定安全门槛停止，不能列为通过。root命名空间只可作为更窄威胁模型的研究方向。

另外，官方`ntfs-3g.probe --readwrite`用可写flags打开引擎，不能替代产品的RO|FORENSIC写前门禁；本轮只执行只读模式。

## 可复查命令

```sh
NTFS_BUILD_ARCH=x86_64 bash script/build_engine.sh
xcodebuild -project NTFSWorkbench.xcodeproj -scheme NTFSWorkbench -configuration Release ARCHS=x86_64 ONLY_ACTIVE_ARCH=NO -derivedDataPath build/xcode-x86_64 CODE_SIGNING_ALLOWED=NO build
NTFS_BUILD_CONFIGURATION=Release bash script/build_and_run.sh --build-only
xcodebuild -project NTFSWorkbench.xcodeproj -scheme NTFSWorkbench -configuration Release ARCHS=arm64 ONLY_ACTIVE_ARCH=NO MACOSX_DEPLOYMENT_TARGET=15.4 -derivedDataPath build/xcode-15.4-arm64 CODE_SIGNING_ALLOWED=NO build
xcodebuild -project NTFSWorkbench.xcodeproj -scheme NTFSWorkbench -configuration Release ARCHS=x86_64 ONLY_ACTIVE_ARCH=NO MACOSX_DEPLOYMENT_TARGET=15.4 -derivedDataPath build/xcode-15.4-x86_64 CODE_SIGNING_ALLOWED=NO build
python3 Tests/Compatibility/build_frontend_candidate.py --compile-only
python3 Tests/Compatibility/build_frontend_candidate.py --link-only
```

最后两条需要先准备本轮固定头文件与独立引擎配置；清洁检出不含生成目录。只读观察器命令见[兼容测试说明](../Tests/Compatibility/README.md)。全部构建证据按相对目录归档于`build/0.2.0/低系统候选验证记录/`、`build/0.2.0/旧系统独立后端/`。这些生成产物不作为公开支持声明，也不含在正式应用中。

## 下一阶段验收标准

1. 15.4路线先找到并独立审查不降低挂载实例保护的正常卸载接口/约束，再集成受控属性补丁和完整低目标构建。
2. 13/14路线在另行明确第三方依赖分发和系统授权方案后，使用真实运行时完成新建镜像的VFS挂载、Finder读写、正常卸载、占用拒绝和恢复测试；运行时缺失必须明确阻断。
3. Intel与每个旧系统都需要实机运行和签名/授权验收。交叉编译、当前26系统运行和离线镜像探测不能替代。
4. 在以上门槛满足前，不降低最低系统，不宣传Intel或旧系统已支持。

变更影响与回滚：正式兼容工程只加入受限架构构建参数与CURRENT_ARCH库路径；默认ARM及26保持。候选观察器和构建工具放在Tests/Compatibility；未改正式卸载策略。最小回滚是撤回架构参数/库路径两处配置并不集成候选，保留验证记录。没有真实旧系统、Intel执行、FUSE挂载、TCC或旧系统性能的覆盖。
