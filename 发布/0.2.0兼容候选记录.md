# 0.2.0 兼容工程候选记录

记录日期：2026-10-29。公开发布范围保持 **macOS 26 及以上、Apple Silicon**。以下是为后续兼容路线完成的工程验证，不是宣布 macOS 13/14/15.4 或 Intel 已可用。没有安装第三方驱动、修改系统安全配置或执行 Intel 程序。

## 固定来源与架构取舍

- [NTFS-3G 官方固定源码](https://github.com/tuxera/ntfs-3g/tree/7f0f841fc52cf719106c5c93bafe465004e36816)：`7f0f841fc52cf719106c5c93bafe465004e36816`。Darwin使用external FUSE，不能直接把Linux fuse-lite当作macOS运行时。
- [macFUSE 官方 C API](https://github.com/macfuse/library/tree/7a6cdd2b6e11071a706f4295aa931c65223ba953)：`7a6cdd2b6e11071a706f4295aa931c65223ba953`。本轮只下载头文件及许可证，保留逐文件校验。
- [macFUSE 官方后端说明](https://github.com/macfuse/macfuse/wiki/FUSE-Backends)：FSKit后端要求15.4起。13/14需要独立后端路线；其内核后端在Apple Silicon上的授权要求见[官方入门](https://github.com/macfuse/macfuse/wiki/Getting-Started)。未为验证而安装或降低系统保护。
- [Apple DiskArbitration 官方源码](https://github.com/apple-oss-distributions/DiskArbitration/tree/a542bda934211dc3c301bfdcc7f21349c4164a85)：`a542bda934211dc3c301bfdcc7f21349c4164a85`。DADiskCreateFromIOMedia最终采用BSD名；异步请求传磁盘ID，daemon重查后按路径unmount。公开请求不携带原FD/预期fsid。
- [Apple XNU 官方源码](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/vfs/vfs_syscalls.c)：`f6217f891ac0bb64f3d375211650a4c1ff8ca1ea`。普通非root挂载需要拥有目标目录，root保护空目录能限制直接覆盖；但实际挂载根owner、允许卸载标志、系统特权服务和并发路径解析不能由空目录权限直接推出。

因此不采用`unmount(path)`替换正式`funmount(fd)`。DADiskClaim的独占声明与保留IOMedia有价值，但没有证明消除检查后到异步路径卸载之间的挂载实例变化窗口，正常/占用/身份变化三类DA卸载原型按既定安全门槛停止，不能列为通过。root命名空间只可作为更窄威胁模型的研究方向。

另外，官方`ntfs-3g.probe --readwrite`用可写flags打开引擎，不能替代产品的RO|FORENSIC写前门禁；本轮只执行只读模式。

## 下一阶段验收标准

1. 15.4路线先找到并独立审查不降低挂载实例保护的正常卸载接口/约束，再集成受控属性补丁和完整低目标构建。
2. 13/14路线在另行明确第三方依赖分发和系统授权方案后，使用真实运行时完成新建镜像的VFS挂载、Finder读写、正常卸载、占用拒绝和恢复测试；运行时缺失必须明确阻断。
3. Intel与每个旧系统都需要实机运行和签名/授权验收。交叉编译、当前26系统运行和离线镜像探测不能替代。
4. 在以上门槛满足前，不降低最低系统，不宣传Intel或旧系统已支持。

变更影响与回滚：正式兼容工程只加入受限架构构建参数与CURRENT_ARCH库路径；默认ARM及26保持。候选观察器和构建工具放在Tests/Compatibility；未改正式卸载策略。最小回滚是撤回架构参数/库路径两处配置并不集成候选，保留验证记录。没有真实旧系统、Intel执行、FUSE挂载、TCC或旧系统性能的覆盖。

## 2026-10-29 无测试盘续作

已从固定 NTFS Git 源和固定官方头文件缓存，在全新目录 `build/0.2.0/离线可复现候选-20261029/` 完整重建双架构静态库（各32个引擎对象）及12个前端对象。15项路径/文件/归档/源码边界测试通过，链接运行时缺失返回78；生产静态库与引擎源码指纹前后无变化。全程只编译和检查普通文件，没有执行任何磁盘挂载、卸载或新的镜像探测。

补查 Apple `ctlbyfsid/VFS_CTL_UMOUNT`：相较路径方案可避免按路径再选卷，但不能把原FD与请求目标在内核内原子绑定。两个固定XNU提交均显示事件观察FD允许随正常卸载回收，通用fsid生成器仅避开当前挂载列表；旧挂载移除后不能证明编号永久不复用。root命名空间及助手内部租约不构成全局编号/挂载租约。六目标ABI编译不替代运行及安全证明，因此不改生产funmount，不降低系统门槛。详细源码、权限、版本边界及剩余窗口见[补充研究](旧系统卸载补充研究.md)。

本轮没有覆盖实际sysctl、FUSE VFS挂载、旧系统/Intel实机和性能；实体20轮仍为待验。最小回滚是不集成候选，仅撤回本轮Tests/Compatibility工具与文档，保留生成证据；生产卸载路径无变更。
