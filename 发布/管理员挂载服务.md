# 管理员挂载服务

物理设备的原始节点可能只允许系统访问。本应用通过 macOS 的 `SMAppService` 注册包内挂载助手，由管理员在系统设置中批准；不会修改设备节点权限、使用 setuid 文件、保存密码或降低系统安全设置。macOS26.4及以上的普通用户测试镜像可按权限走前台挂载；较早受支持系统的受管挂载使用管理员服务，不能将镜像所有权当作绕过服务与身份核验的条件。

0.3.0已交付Intel与Apple Silicon通用包，主程序、助手与兼容前端最低macOS13。15.4及以上使用FSKit；13～15.3使用用户自行安装批准的官方macFUSE。下文的历史真实介质验收不扩大为这些组合全部通过；Apple虚拟机的旧内核路径还有独立限制。

## 范围

### 0.3.1（构建8）私有候选路由（尚未发布）

构建8源码已整合为[候选源码提交](https://github.com/dososo/ntfs-writeflow/commit/23479279258f1887eada9c6d6b676d9583d92c05)，尚无正式Release或客体完整链通过。本轮15.4～26.3只读由管理员服务调用系统`diskutil`原生NTFS；15.4至26以前读写使用独立身份桥接。26.0～26.3的RO／RW均强制经助手，RW系统命令与可信`SUDO_UID`发现方式保持；26.4起只读／读写均FSKit并按介质权限路由。公开`requestedMountOptions`到26.4才可用，26及以上的`funmount`保留。26.0～26.3只有策略／模拟回归，没有实际对应系统通过。相关开发回归通过，构建8的15.4客体完整链待验，不改变下文历史验收范围。

所有新请求须检查同整盘旧未决原生只读票据；失败清理按本次命令是否有界及是否未决决定保留，不能按系统版本一概清除。该组合缺口已完成开发回归和独立审查闭环；原生只读69项、身份桥接72项、受管发现85项均两架构通过，完整核心／模型runner退出0，仍不能代替客体完整链。原生只读还须核验实际`ntfs`类型、root所有者、只读位、介质／挂载实例和持有句柄，不把任意系统NTFS卷认作本应用。

15.4身份桥接、关闭扩展拒绝及b41候选原生只读GUI分项已有实际记录；b41的RW创建EROFS，f9后续内部RW仍发生资源能力拒绝、EIO和正常卸载失败。构建8尚待真实根属性、GUI读写、忙句柄和正常收尾完整链。旧FSKit读写的`nosuid`／`nodev`／`nobrowse`未全部保留；扩展拒绝Interix特殊项、不呈现setuid／setgid是独立约束，不证明内核安全标志生效。详细失败对照见[可核验说明](0.3.1可核验说明.md)。

### 旧FSKit内部准备与准确状态（私有候选）

仅15.4及以上、26以前的受管FSKit读写挂载使用新准备协议，原生RO、macFUSE和26及以上不走这项握手。助手把票据nonce与mediaID传入固定挂载调用；扩展先保RO，普通后台修改不能抢先升级。原资源公开`metadataFlush`能力失败，以及原RO仍存活阶段只读预检／身份拒绝时，保RO并锁存原错误；零数据写回和正常只读清理目前只有普通文件开发证据，没有目标FSBlock通过结论。

挂载成功回包前，助手从精确受管挂载点持有事件目录FD，传给已验签的票据专用root助手副本作为FD0。私有模式不接收任意路径／命令／运行时，检查root身份、缓存副本、票据及继承FD，把CLOEXEC设回后，在租约保护下对根项读取最多1024字节的nonce准备属性；前后复核FD／路径FSID、来源、所有者与两层介质。执行仍未知的探针保留租约，正常卸载不能绕过其互斥；超时不是取消完成，也不能删票据继续。

首次操作使用prepare，恢复／刷新仅使用被动status，不能由查询启动RO→RW。回执须是固定四字段`schema/token/mediaID/writable`且全部绑定匹配，不能相信磁盘存储的同名属性。`writeReady`独立于内核只读标志；缺失或失败时应用显示“写入未就绪”，保留正常卸载入口。客户端被动查询预算2秒，返回后再次读取受影响设备当前实例，同media重挂为新token／FSID也不能套用迟到的true；消失或读取失败撤旧记录并按新清单裁剪绑定。

阶段四[修复2347927](https://github.com/dososo/ntfs-writeflow/commit/23479279258f1887eada9c6d6b676d9583d92c05)已修复原先的预检收尾P1并完成独立只读审查：仅旧系统分支把只读quickcheck、身份复核及后端包装器创建前置到原RO关闭之前，拒绝时锁存原错并保RO。暂持包装器未转移时精确清理，成功后才消费RO并开启RW引擎；原RO关闭失败或RW引擎开始后的真实错误仍拒绝，不把空handle的同步改成成功。第一份构建8因该P1阻断，证据保留、制品不可用，不以相同版本号混作阶段四候选。

这项内部探针的根FD由助手自行取得；正常卸载仍使用下述前台授权并通过XPC传入的根FD。二者不能混称为“助手永不打开受管根目录”，也不能由普通文件stdin测试推断真实TCC／FSKit已通过。

### 服务与卸载边界

- 服务标识：`com.blteam.ntfsworkbench.mount-helper`。
- 可执行文件：应用包内 `Contents/Library/HelperTools/NTFSWriteFlowMountHelper`。
- 配置：应用包内 `Contents/Library/LaunchDaemons/com.blteam.ntfsworkbench.mount-helper.plist`。
- 仅接受正式签名的本应用连接；双方均由系统检查精确标识及签名团队，不按可能复用的进程号判断身份。
- 执行经过介质身份核验的外部 NTFS 挂载、受管挂载查询、同步后正常卸载与整盘推出前的准备；最终原始设备推出由前台应用执行。没有任意命令、任意路径、格式化、修复、强制卸载或自动抢占接口。
- 挂载路径由助手生成，按连接用户隔离。目录及凭据由系统拥有，用户只有必要的查看和遍历权限，不能替换用于系统挂载的目录。
- 卸载由前台应用在用户上下文打开事件目录句柄，经 XPC 传给助手。助手再次核验目录类型、精确挂载根路径、事件打开标志、票据、介质与挂载实例后执行同步和正常卸载；不在后台重新打开受隐私保护的卷路径，也不要求增加完全磁盘访问权限。26及以上保留按文件句柄卸载；较早系统使用root私有一次性目录、租约和身份复核下的正常路径卸载，不具备抵抗其他root进程绕过仲裁重挂同一路径的原子保证。同步、占用或兼容后端最终关闭失败均不报告干净完成；兼容后端挂载点消失也不能替代最终回执。

阶段四三runner双架构和六目标检查全0，独立只读审查未发现确定P0／P1；0.3.1（8）通用Release构建、正式签名、strict校验通过，但未公证、未做新候选VM验收、未发布。签名检查不替代系统挂载或公证结论。

## 配置与移除

在“设置 → 物理磁盘挂载”中选择配置服务。只有系统实际批准后，应用才会使用该服务。系统报告“已获授权”与一次挂载操作成功是不同状态；操作仍须核对实际挂载类型、介质和读写模式。

系统批准、后台登记、进程实际启动与成功XPC事务须分别核验。单凭设置中的“已获授权”或BTM允许记录，不能证明助手已经运行；查询失败也不能算客户端签名拒绝测试通过。

需要移除时，先关闭使用卷的文件并正常卸载所有受管卷，再在同一页面选择移除服务。系统也提供后台项目管理入口。卸载应用前应先移除服务，不要在卷仍挂载时删除应用包或助手。

## 整盘推出与系统授权

前台先正常卸载本应用管理的同盘卷，并提供其他同盘挂载根的事件句柄。管理员服务通过 `prepareEject` 重新核对原介质、同盘清单与全部根句柄，再逐卷同步并正常卸载；回复前确认同盘无挂载并关闭自己接收的根句柄。服务不执行最后的原始设备推出。

前台关闭自己的根句柄后，取得精确整盘设备的只读授权。普通只读打开被拒绝时，使用系统授权工具申请句柄，可能显示 macOS 认证窗口。由本人在该系统窗口完成 Touch ID 或密码认证；不向聊天或应用自定义表单提供凭据。取消或失败时停止后续操作，分卷可能已经卸载，但不能提示整盘已退出。

前台应用在后台队列再次核验原两层介质登记标识、稳定容量、外部属性、字符设备号及空挂载清单，并保持同一个只读设备描述符提交 `DKIOCEJECT`。占用只做有界等待，每次重试都复核原对象和空挂载状态；不关闭重开设备，不强制卸载或推出。没有改变后台服务的磁盘隐私权限，也不需要完全磁盘访问。

请求成功后关闭原始句柄，再核对结果：镜像和可移除介质要求原对象消失；原始及当前属性均明确为外部、不可机械弹出、不可移除的固定硬盘，只有原介质身份及容量一致、同盘无挂载、整个介质树的 `Open` 均为 `false` 才允许返回“已安全推出，设备仍连接，可以断开”。缺少成功回执、属性未知、仍有挂载或打开引用均不算完成。应用随后再次回读清单，刷新发现重新挂载时撤销本会话已推出状态。

实际外部固定 USB 硬盘已通过 GUI 操作与独立系统回读，未新增真实盘测试写入；新建测试镜像也通过 GUI 弹出、映射及原对象消失和离线文件摘要复核。这些结果不扩大为所有介质、异常拔插、Windows 或长期稳定性通过。具体实现见 `Sources/HelperShared/DiskEject.swift`、`Sources/App/Services/AuthorizedDeviceHandle.swift` 与 `Sources/PrivilegedHelper/HelperEject.swift`。

## 开发和验证

构建8共享协议／应用状态81项、可挂起RPC实例重读12项及既有32＋58＋23项双架构通过；助手完整核心两架构通过，含18项私有参数、stdin CLOEXEC继承和超时未知结果。真实普通镜像能力／nonce回归及全应用界面严格类型检查通过；没有以此声称root根xattr、真实FSKit或VM完整链通过。复现命令与六项边界见[可核验说明](0.3.1可核验说明.md)。


2026-11-05在ARM Apple虚拟机实际运行13.7.4（22H420）与14.0（23A339），原版与正式签名0.3.1候选的安装、签名／Gatekeeper检查，以及候选设置／诊断窗口滚动触达和文件导出均有实际记录。镜像原标签13.6不能当作13.6验收。

14.0服务批准后存在system域登记，但运行次数为0；13.7.4产品显示已获授权、BTM的daemon为enabled／allowed，`launchctl`仍未找到服务，登记／运行状态差异待单独分析。本轮没有成功XPC挂载事务，不能将授权交互当作管理员完整链通过。

两台客体均安装官方macFUSE5.5.0但内核加载未获准；原版仍显示运行时就绪的误导已复现，候选明确拒绝不支持的Apple虚拟机挂载。真实NTFS VFS首步失败，后续RO／RW、文件系统卸载及收尾未通过；测试镜像正常分离且摘要未变。该平台限制见[macFUSE官方说明](https://github.com/macfuse/macfuse/wiki/Getting-Started)，15.4及以上本应用的FSKit路径不按此规则禁用，结果需独立验收。

本轮CI来源客体起始SIP disabled、Authenticated Root enabled、Gatekeeper enabled；14.0尝试恢复SIP时被Apple个性化签名请求错误132拒绝，未恢复成功。没有降低安全绕过，不将其作为默认安全实体Mac支持结论。以下2026-10-25的历史真实介质记录保留原范围。

共享协议在 `Sources/HelperShared`，助手在 `Sources/PrivilegedHelper`，应用客户端在 `Sources/App/Services/PrivilegedMountClient.swift`。发布者使用自己的证书重新签名时，应同步修改共享配置中的精确团队要求，并重新执行双方身份拒绝测试；不能删除签名检查来让临时签名版本通过。

2026-10-25 的真实验收已经完成服务系统授权、正式应用只读和读写挂载、普通用户访问、指定新建目录写入同步、正常卸载及独立驱动复读，随后恢复原驱动挂载。挂载实际所有者为 root。系统挂载程序使用仅由助手传入的可信连接用户标识发现用户已启用的 FSKit 模块，同时保留访问设备所需的有效 root 身份；不会改变助手进程本身的身份或向其他命令传递该环境。

同一助手进程接受正式应用的合法挂载调用后，拒绝了错误签名探针的只读查询，随后继续接受正式应用的正常卸载调用。系统日志明确记录与探针进程对应的签名要求拒绝。探针自身仅输出“未判定”，不能把服务失联、普通 XPC 错误或超时当成签名保护通过。

上述记录限于本次真实介质与指定目录，不是全盘既有内容校验，也不等于 Windows 兼容性、真实跨用户隔离、助手进程重启恢复、异常拔插或断电验收。静态审查和非特权策略测试仍不能替代这些系统验证。最终分发签名、公证与干净环境结果应单独核对，不以成功构建或本次读写闭环代替完整发布门禁。
