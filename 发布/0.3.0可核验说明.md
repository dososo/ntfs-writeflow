本说明区分交付行为、可复现检查与未覆盖场景。版本为 0.3.0（6），通用兼容预览。

| 可检查行为 | 实现位置 | 验证入口 |

## 复现入口

```sh
NTFS_BUILD_CONFIGURATION=Release bash script/build_and_run.sh --build-only
python3 script/check_app_architecture.py --app build/xcode/Build/Products/Release/NTFSWorkbench.app --require-legacy
python3 -m unittest discover -s Tests -p 'test_*.py'
NTFS_TEST_ARCH=arm64 bash Tests/Core/run_eject_tests.sh
NTFS_TEST_ARCH=x86_64 bash Tests/Core/run_eject_tests.sh
NTFS_TEST_ARCH=arm64 bash Tests/Core/run_automount_tests.sh
NTFS_TEST_ARCH=x86_64 bash Tests/Core/run_automount_tests.sh
python3 Tests/LegacyBackend/run.py
python3 Tests/System/旧路径正常卸载.py
```

测试工具依赖与官方运行时只读制品前置见相应测试说明。x86_64 命令在本机通过已存在的 Rosetta 执行；测试不自动安装 Rosetta。全部磁盘类入口仅针对本轮新建文件镜像，不能复制历史设备号操作现有盘。历史 `Tests/Compatibility` 是 0.2.0 隔离研究工具，当前正式构建用上述生产脚本，不把旧原型的预期编译失败当作本版结果。

## 推断、人工确认与未覆盖

最低系统与双架构检查证明包的静态目标正确；当前系统的 ARM／Rosetta 执行证明已测代码在该环境可运行。两者不证明旧系统内核、Intel 硬件、真实系统批准或实际外接盘均已通过。macOS 13～15.3 还需要用户安装并批准官方 macFUSE。旧路径卸载不抵抗另一个 root 进程绕过仲裁直接重挂同一私有路径；macOS 26 仍使用文件句柄原子路径。

未覆盖项目和兼容路径见[发行说明](0.3.0兼容预览发行说明.md)。当前环境已有第三方 NTFS 驱动，自动管理会按保护规则暂停；注入环境的成功不等于无竞争环境接入已验收。真实登录、跨用户、掉电、Windows 与实体长期压力均需单独完成。

## 最小回滚

代码回滚为撤回本版兼容提交并重建旧版本，不清理用户盘或系统保护设置。已安装用户先关闭自动管理，等待事务完成、正常卸载自有卷并移除服务，再替换应用。收尾错误必须保留失败凭据与诊断，不能删锁强行继续。macOS 26 Apple Silicon 可退到 0.2.0；其他系统退回系统只读／原工具。发行附件中的源码和二进制对应记录提供精确版本回溯。
